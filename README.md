# مانو کید (MANO Kid)

اپ وب فارسی و راست‌به‌چپ با React، TypeScript، Tailwind CSS و Express برای توسعه و بررسی داخلی ابزارهای آموزشی مراقبت کودک.

**وضعیت: نامزد بررسی داخلی؛ تأیید انتشار بالینی ندارد.** تأیید انسانی محتوای بالینی، آزمون کاربران و دستگاه واقعی و بررسی پیکربندیِ مستقر همچنان لازم است. از دادهٔ ساختگی برای آزمایش استفاده کنید. حساب و مشاورهٔ آنلاین، اختیاری و در تنظیم پیش‌فرض غیرفعال‌اند.

## مسیرهای اجرا

- `/`: اپ React از `src/main.tsx` و `src/App.tsx`، همراه با ناوبری، پروندهٔ محلی و ابزارهای آموزشی.
- `/preview/`: طرح قبلی Care Home با `src/app.js`؛ دموی مستقل بدون API و بدون ذخیرهٔ اطلاعات پس از تازه‌سازی.
- `/api/health`: وضعیت عمومی و خلاصهٔ سرویس؛ بدون تنظیمات مدل، بودجه یا لاگ کاربران.

هر دو ورودی وب با Vite در `dist/` ساخته می‌شوند. پوشهٔ `app/` منابع جداگانهٔ Kotlin دارد؛ اجرای وب، APK تولید نمی‌کند.

## اجرا

```bash
npm ci
npm run dev
```

برنامه روی `http://localhost:3000` اجرا می‌شود. برای بررسی خروجی ساخته‌شده:

```bash
npm run build
NODE_ENV=production npm start
```

## امکانات و محدودیت‌ها

- ابزارهای محلی شامل محاسبهٔ آموزشی داروی مایع، بررسی علائم، رشد WHO، واکسیناسیون و برنامهٔ مراقبت هستند. معتبر بودن پیاده‌سازی به معنی تأیید بالینی آن‌ها نیست.
- محاسبه‌گر دوز، سن یا وزن نامعلوم را تخمین نمی‌زند؛ واردکردن مقادیر معتبر و تأیید برچسب لازم است. سن اعشاری حفظ می‌شود و اختلاف سن با تاریخ تولد، محاسبه را تا اصلاح پرونده متوقف می‌کند. تغییر سن، وزن یا فرآورده تأیید را باطل می‌کند؛ ثبت مصرف از محاسبه‌گر به تأیید جداگانهٔ مصرف واقعی نیاز دارد.
- ثبت دما و دارو بدون مقدار نمونه شروع می‌شود و مقدار واقعی، روش/فرآورده و زمان رخداد را می‌خواهد. زمان رخداد از زمان ورود اطلاعات جداست؛ ثبت سابقه، توصیهٔ مصرف دارو نیست.
- برنامهٔ مراقبت تازه بدون دارو آغاز می‌شود. نمونه‌های نسخهٔ قدیمی به آرشیو بررسی‌نشده منتقل می‌شوند؛ یادداشت‌ها و داروهای سفارشی حفظ می‌شوند. یادآور خودکار در این نسخه فعال نیست.
- چک‌لیست روزانه با تقویم محلی دستگاه محاسبه می‌شود؛ تیک‌های روز قبل یا نمونه‌های قدیمیِ بدون تاریخ، انجام‌شدهٔ امروز شمرده نمی‌شوند.
- اپ React اطلاعات را در `localStorage` همان مرورگر نگه می‌دارد. این ذخیره‌سازی، حساب کاربری یا پروندهٔ ابریِ احرازشده نیست؛ روی دستگاه مشترک از اطلاعات واقعی بیمار استفاده نکنید.
- رابط مرورگر کلید Gemini یا توکن دسترسی سرور را دریافت نمی‌کند. همهٔ درخواست‌های بالینی AI در خود مرورگر، پیش از ارسال تصویر یا اطلاعات کودک رد می‌شوند؛ صرفاً افزودن کلید یا فعال‌بودن وضعیت عمومی سرور آن‌ها را مجاز نمی‌کند. درخواست سلامت عمومی حاوی اطلاعات کودک نیست.

## ذخیره‌سازی و حذف محلی

حذف اطلاعات، شناسهٔ نسخهٔ ذخیره‌سازی را تغییر می‌دهد، سوابق را حذف و فرم‌ها و هشدارهای تب‌های باز همین نسخه را بازنشانی می‌کند. ذخیره و حذف با Web Locks مرورگر هماهنگ می‌شوند؛ نوشتن دوبارهٔ نسخهٔ حذف‌شده رد می‌شود. شناسهٔ حذف حاوی اطلاعات بالینی نیست و برای جلوگیری از بازگشت داده‌ها باقی می‌ماند.

اگر مرورگر قفل ذخیره‌سازی یا دسترسی لازم را نداشته باشد، ذخیره‌سازی پایدار انجام نمی‌شود و خطا در صفحه نمایش داده می‌شود. شکست حذف نیز به‌جای پیام موفقیت گزارش می‌شود. این مکانیزم جایگزین حساب کاربری، جداسازی چند کودک یا پشتیبان‌گیری نیست.

در «پرونده کودک»، بخش پشتیبان، فایل رمزدار با گذرواژهٔ ۱۲ تا ۲۵۶ نویسه می‌سازد: AES-256-GCM و PBKDF2-SHA256 با ۶۰۰٬۰۰۰ تکرار. فایل و گذرواژه ارسال نمی‌شوند؛ سقف دادهٔ بازشده ۲ مگابایت و سقف فایل ۴ مگابایت است. فایل را باز و خلاصه را بررسی کنید؛ جایگزینی همهٔ ثبت‌های محلی، تأیید جداگانه دارد و ادغام خودکار انجام نمی‌شود. بدون گذرواژه، بازیابی امکان‌پذیر نیست. بازیابی، تأیید بالینی یا تأیید مجدد بطری ایجاد نمی‌کند.

اگر دادهٔ محلی قابل خواندن نباشد، نسخهٔ خام آن حفظ و نوشتن خودکار متوقف می‌شود. پیام بازیابی باقی می‌ماند تا کاربر فایل معتبر را صریحاً جایگزین یا اطلاعات را آگاهانه پاک کند؛ مقادیر خالی، جای دادهٔ خراب ذخیره نمی‌شوند.

## حساب و مشاورهٔ آنلاین اختیاری

کد وب، Firebase Auth با نشست حافظه‌ای، App Check، رضایت نسخه‌دار، بررسی مقدماتی سمت سرور و انتخاب داروخانه را پشتیبانی می‌کند. اتصال در `.env.example` پیش‌فرض خاموش است. شناسه‌های عمومی Firebase، سرویس Auth و دامنه‌های App Check باید برای staging واقعی تنظیم و آزموده شوند؛ فعال‌کردن build، مجوز سرویس بالینی سرور نیست.

ورود، پروندهٔ محلی را به حساب پیوند یا منتقل نمی‌کند. فرم آنلاین اطلاعات انتخاب‌شده را جداگانه و با رضایت صریح دریافت می‌کند؛ پاسخ حساب قبلی پس از تغییر نشست نمایش داده نمی‌شود. درخواست‌ها با اعتبارنامهٔ همان حساب آماده و پیش از ارسال دوباره کنترل می‌شوند. حساب والد پیش از ارسال اطلاعات به تأیید ایمیل نیاز دارد؛ دسترسی داروساز علاوه بر نقش، به عضویت زندهٔ همان داروخانه وابسته است.

پاک‌سازی مرورگر، حذف حساب ابری نیست. گردش‌کار حذف حساب، سیاست نگهداری مصوب و پیکربندی مستقل لازم دارد و پیش‌فرض فعال نیست. رسید خصوصی، وضعیت پردازش و سوابق نگه‌داشته‌شده را تفکیک می‌کند؛ پاک‌شدن فیزیکی نسخه‌های پشتیبان زیرساخت از روی رسید فرض نمی‌شود.

## مرز دسترسی API

تمام مسیرهای `/api/gemini/*` به پرچم `MANO_CLINICAL_SERVICE_ENABLED=true` و `Authorization: Bearer ...` معتبر نیاز دارند. توکن باید در `MANO_GATEWAY_ACCESS_TOKEN` روی سرور تنظیم شده باشد. تنظیمات نمونه در `.env.example` هستند؛ آن‌ها را از طریق محیط فرایند سرور تأمین کنید.

توکن را با حداقل ۳۲ بایت تصادفی رمزنگارانه بسازید؛ برای نمونه:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

این توکن فقط برای فراخوانِ سروریِ مورد اعتماد است؛ هویت والد یا داروساز را تأیید نمی‌کند. آن را در `VITE_*`، کد مرورگر، مخزن، URL یا تنظیمات build قرار ندهید. مسیر audit نیز بدون توکن قابل دسترسی نیست و پاسخ‌های حفاظت‌شده `no-store` هستند. کلید Gemini همچنان فقط روی سرور قرار می‌گیرد.

کلاینت حساب و مشاورهٔ داروساز، مجوزی برای فعال‌کردن AI مولد نیست؛ اتصال مرورگر به AI غیرفعال می‌ماند. قفل مشترک انتشار، جایگزین تأیید مستقل تنظیمات Firebase و App Check یا امضای بالینی نیست. درگاه آزمایشی Express همچنان ممیزی و بودجهٔ حافظه‌ای دارد و برای AI چندنمونه‌ایِ عمومی آماده معرفی نمی‌شود؛ مسیر مشاورهٔ Firebase از کنترل‌های ماندگار و تراکنشی خود استفاده می‌کند.

## بررسی و تست

```bash
npm run check
npm run build
npx playwright install --with-deps chromium
npm run test:browser
```

`check` شامل TypeScript، ESLint، آزمون‌های بالینی، بازیابی، رمزگذاری و مرز دسترسی HTTP و آنلاین است. تست مرورگر روی خروجی واقعی build اجرا می‌شود و علاوه بر قفل‌های بالینی، تمرکز پنجره‌ها، متن بزرگ، تغییر روز دستگاه، پشتیبان و دادهٔ خراب را بررسی می‌کند. با `MANO_BROWSER=firefox` همان مجموعه روی Firefox اجرا می‌شود؛ CI هر دو مرورگر را می‌آزماید. workflow دستی نیز نسخهٔ انتخاب‌شده را می‌آزماید.

تست‌ها از پاسخ ساختگی استفاده می‌کنند و به Gemini درخواست واقعی نمی‌فرستند. موفقیت آزمون‌ها به معنی مجوز انتشار بالینی نیست؛ ثبت امضاها در `docs/CLINICAL_SIGNOFF_REGISTER_2026-11-21.md` و معیارهای انتشار موجود باید جداگانه تکمیل شوند.

گزارش [بازبینی انتقادی ساختار و تجربهٔ کاربری](docs/UX_UPGRADE_REVIEW_2026-11-27.md) شامل تصاویر قبل و بعد، منابع تصمیم‌های طراحی، نتیجهٔ آزمون‌ها و شناسهٔ مراحل ذخیره‌شده در `main` است.

برای ساخت، کانال آزمایشی و بازگشت نسخه، [راهنمای انتشار وب](docs/WEB_RELEASE_RUNBOOK_2026-11-27.md) را ببینید. تنظیم مستقل `firebase.web.json` خروجی React در `dist` را سرو می‌کند؛ فایل موجود `firebase.json` برای backend دست‌نخورده است. شناسهٔ درخواست و خطاهای ۵xx بدون URL، بدنه، IP یا شناسهٔ حساب قابل ثبت‌اند؛ موفقیت عادی کاربران، گزارش فعالیت ایجاد نمی‌کند. هیچ استقرار عمومی در این مرحله انجام نشده است.
