# چک‌لیست نهایی اتصال داخلی MANO به لیارا
**فقط داده ساختگی. انتشار عمومی و فعال‌سازی بالینی مجاز نیست.**

## گام ۱ — محیط موجود را حفظ کنید
- نسخه فعال manokid.com و شاخه استقرار فعلی تغییر نکند؛ استقرار خودکار خاموش.
- رمز مدیر PostgreSQL که قبلاً نمایش داده شده تعویض شود. هیچ رمز یا URI به GitHub یا چت ارسال نشود.
- دسترسی عمومی دیتابیس خاموش، شبکه خصوصی مشترک با برنامه بررسی شود.

## گام ۲ — ایجاد محیط مستقل
- ابتدا CI همین commit باید موفق باشد.
- مدیر مجاز دیتابیس، پایگاه جداگانه mano_stage و نقش غیرمدیر mano_stage_app را ایجاد کند. نقش مالک schema و runtime جدا باشند؛ نقش runtime نباید عضو نقش مالک یا BYPASSRLS باشد.
- فقط روی پایگاه جدید و خالی، schema.sql را در یک تراکنش با حساب مهاجرت اجرا کنید. از اجرای آن روی postgres یا پایگاه واقعی خودداری کنید.
- در کنسول داخلی، متغیر MANO_STAGE_DATABASE_URL را با URI نقش محدود و پایگاه mano_stage ثبت کنید. حالت MANO_STAGE_DB_TLS=verify-full و CA معتبر ترجیح داده شود. حالت private-test فقط برای داده کاملاً ساختگی، نه بیمار.
- این سرویس روی loopback اجرا می‌شود و به وب فعال متصل نیست. برای آزمایش داخلی می‌توان از محیط کنترل‌شده دارای دسترسی شبکه خصوصی استفاده کرد؛ به پورت عمومی یا reverse proxy وصل نشود.
- در independent-backend با Node 24 و npm ci نصب کنید. node preflight.mjs فقط چک‌های بولی اتصال و مجوزها را گزارش می‌کند. اگر یکی ناموفق بود توقف کنید.
- توکن محیط آزمایشی و کلید OTP را مستقل و تصادفی تولید کنید. تا زمان آزمایش کنترل‌شده، MANO_INDEPENDENT_STAGE_ENABLED و MANO_STAGE_DEMO_AUTH_ENABLED هر دو false باقی بمانند.

## گام ۳ — معیار خروج از آزمایش
| آزمون | شرط پذیرش |
|---|---|
| CI PostgreSQL | همه آزمون‌ها برای همین commit موفق |
| اتصال خصوصی | preflight موفق، نقش محدود، عدم دسترسی عمومی |
| والدین | عدم امکان خواندن یا تغییر پرونده خانواده دیگر |
| داروساز | دسترسی فقط به اشتراک دارای رضایت و عضویت فعال |
| OTP | انقضا، محدودیت تلاش، عدم استفاده مجدد، عدم افشای کد |
| Audit | ثبت حداقلی، دسترسی مدیریتی محدود و سیاست نگهداری مصوب |
| بازیابی | آزمون پشتیبان واقعی پایگاه جداگانه، علاوه بر نمونه رمزنگاری |
| مهاجرت | موجودی خواندنی، تطبیق مالکیت، شمارش، تعارض، عدم حذف مبدأ |
| انتشار | بررسی امنیت، حریم خصوصی، تایید داروساز، دستگاه واقعی و آزمون Firefox |

## گام ۴ — خارج از محدوده این نسخه
پیامک ایرانی واقعی، ثبت نام، بازیابی هویت، احراز داروساز، پرونده سلامت واقعی، انتقال Firebase، اتصال رابط وب و اندروید، مهاجرت کامل و حذف داده با سیاست نگهداری هنوز پیاده‌سازی یا تأیید نهایی نشده‌اند. قبل از انتخاب ارائه‌دهنده پیامک و طراحی قرارداد API آن، هیچ هزینه جدید لازم نیست. کلیدهای بالینی و Firebase فعلاً خاموش بمانند. در صورت شکست، محیط فعال بدون تغییر باقی می‌ماند؛ مرحله آزمایشی را متوقف کنید، نه اینکه حفاظت‌ها را حذف کنید.
